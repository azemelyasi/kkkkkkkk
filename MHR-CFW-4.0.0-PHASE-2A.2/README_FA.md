# MHR CFW 3.0.0 — Windows 11 / Python Edition

این بسته یک لانچر Python برای موتور MHR موجود در نسخه 2.0.0 و یک هسته جانبی sing-box است. برنامه با `run.bat` اجرا می‌شود.

## امکانات

- اجرای موتور اصلی MHR با Python و محیط مجازی محلی (`.venv`).
- پراکسی HTTP روی `127.0.0.1:8085` و SOCKS5 روی `127.0.0.1:10808`.
- فعال/بازگردانی پراکسی کاربر ویندوز برای مرورگرهایی که از System Proxy استفاده می‌کنند. تنظیم قبلی ویندوز ذخیره و پس از خروج بازگردانی می‌شود.
- گزینه نصب CA محلی فقط با تأیید صریح کاربر؛ کلید CA جدید روی همان دستگاه ساخته می‌شود.
- حالت TUN اختیاری با هسته رسمی sing-box که در اولین استفاده، از GitHub رسمی دریافت و با SHA-256 ارائه‌شده در Release بررسی می‌شود.
- DNS در TUN از DoH و از مسیر TCP پراکسی MHR عبور می‌کند. چون SOCKS5 فعلی MHR فقط `CONNECT` را پیاده‌سازی کرده و `UDP ASSOCIATE` ندارد، UDP عمومی (از جمله QUIC) در TUN رد می‌شود تا مرورگرها در صورت امکان به TCP برگردند.

## پیش‌نیازها

- Windows 11 x64
- Python 3.10 یا جدیدتر، همراه با گزینه Add Python to PATH
- برای TUN: اجرای `run.bat` با Run as administrator و دسترسی به GitHub برای دریافت sing-box
- برای کارکرد رله: Deployment شخصی Google Apps Script و Cloudflare Worker که خودتان پیکربندی کرده‌اید

## راه‌اندازی

1. ZIP را استخراج کنید.
2. `run.bat` را اجرا کنید. در اولین اجرا، وابستگی‌های Python نصب و پنجره تنظیمات باز می‌شود.
3. در Google Apps Script یک پروژه بسازید و محتوای `script/Code.gs` را وارد کنید.
4. **Secret سمت GAS (اجباری):** در Apps Script به منوی *Project Settings → Script properties* بروید و این کلیدها را اضافه کنید:
   - `AUTH_KEY` = همان رمز تصادفی قوی که در `config.json` به‌عنوان `auth_key` می‌گذارید
   - `WORKER_URL` = آدرس کامل Worker شما (مثلاً `https://name.subdomain.workers.dev`)
   - اختیاری: `AUTH_KEY_PREV` فقط هنگام چرخش Secret
   **رمز را داخل متن `Code.gs` قرار ندهید.**
5. فایل `script/worker.js` را در Cloudflare Workers منتشر کنید. در داشبورد Worker یک **Secret** با نام `AUTH_KEY` بسازید (همان مقدار `auth_key` / GAS). اختیاری: `AUTH_KEY_PREV` برای چرخش.
6. Web App مربوط به Apps Script را Deploy کنید و Deployment ID را در Wizard وارد کنید. مقدار `auth_key` در `config.json` باید دقیقاً با Script Property `AUTH_KEY` و Workers Secret `AUTH_KEY` یکسان باشد.
7. در منوی برنامه، گزینه 3 را فقط در صورت نیاز و پس از مطالعه هشدار، برای نصب CA انتخاب کنید.
8. گزینه 1 را برای پراکسی مرورگرها انتخاب کنید. Firefox را روی «Use system proxy settings» قرار دهید اگر تنظیم ویندوز را خودکار دنبال نمی‌کند.

### هماهنگی Secret (Phase 2A)

| محیط | محل ذخیره Secret |
|------|------------------|
| Python | `config.json` فیلد `auth_key` (محلی؛ در Git/ZIP قرار ندهید) |
| Google Apps Script | Script Properties → `AUTH_KEY` |
| Cloudflare Worker | Workers Secrets → `AUTH_KEY` |

هر سه باید یک مقدار یکسان داشته باشند. Secretهای افشاشده قبلی را دوباره استفاده نکنید.

## حالت‌ها

- **Browser Proxy (پیشنهادی):** فقط برنامه‌هایی را پوشش می‌دهد که از پراکسی سیستم ویندوز استفاده می‌کنند. مرورگرهایی که تنظیم پراکسی مستقل دارند باید جداگانه تنظیم شوند.
- **TUN (اختیاری):** مسیر شبکه کل سیستم را تغییر می‌دهد، نه فقط مرورگرها. به Administrator و درایور/پشتیبانی TUN ویندوز نیاز دارد. اگر MHR متوقف شود، لانچر TUN را متوقف می‌کند تا ترافیک ناخواسته به مسیر مستقیم نیفتد.

## محدودیت‌های مهم — شفافیت فنی

- هیچ پراکسی‌ای نمی‌تواند تضمین کند تمام سایت‌ها در تمام شبکه‌ها باز شوند؛ رله، سهمیه Google Apps Script، Worker، DNS و سیاست سایت مقصد همگی مؤثرند.
- MHR فعلی UDP را در SOCKS5 پشتیبانی نمی‌کند. در TUN، UDP عمومی رد می‌شود؛ DNS از DoH عبور می‌کند و QUIC باید به TCP fallback کند. تماس‌های صوتی/تصویری، بازی‌ها، STUN و سایر سرویس‌های UDP ممکن است کار نکنند.
- TUN در این نسخه از sing-box به‌عنوان لایه مسیریابی استفاده می‌کند؛ خود sing-box به‌تنهایی سرویس خروجی اینترنت یا اشتراک VPN تولید نمی‌کند و برای خروجی TCP به MHR پیکربندی‌شده وابسته است.
- حالت TUN روی شبکه واقعی و سخت‌افزار Windows 11 کاربر نهایی در این محیط قابل آزمایش نبود؛ قبل از استفاده روزمره، با چند سایت و DNS test کنید.

## امنیت

- فایل ZIP اولیه حاوی کلید خصوصی CA و رمز ثابت Apps Script بود. این نسخه آن‌ها را عمداً حذف کرده و هیچ `config.json` واقعی را بسته‌بندی نمی‌کند. راز قبلی را افشاشده فرض کنید و دوباره استفاده نکنید.
- کلید CA در اولین استفاده ساخته می‌شود و نباید با دیگران به اشتراک گذاشته شود. نصب CA به معنی اعتماد سیستم به گواهی‌های صادرشده توسط پراکسی محلی است؛ فقط اگر به سورس و دستگاه خود اعتماد دارید نصب کنید.
- پراکسی فقط روی loopback (`127.0.0.1`) گوش می‌دهد و اشتراک‌گذاری LAN به‌صورت پیش‌فرض خاموش است.
- برای بازگردانی پراکسی ویندوز از گزینه 6 یا خروج عادی از حالت Browser Proxy استفاده کنید.

## پورت‌ها

| سرویس | پورت |
|---|---:|
| HTTP Proxy | 8085 |
| SOCKS5 TCP CONNECT | 10808 |
| TUN DNS address | 172.19.0.2 (داخلی) |

این پورت‌ها روی کامپیوتر محلی هستند و نیازی به باز کردنشان روی روتر یا اینترنت نیست.
